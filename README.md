# Анализ показаний водосчётчиков

Python-скрипт для расчёта суточного расхода из накопительных показаний и поиска подозрительных ситуаций. Исходный архив задания в репозитории не хранится: положите три CSV в `data/source/`.

## Запуск

Нужен Python 3.10 или новее.

```powershell
python -m pip install -r requirements.txt
python analyze_water_meter_data.py --input-dir data/source --output-dir results/generated
```

Скрипт ожидает `pokazaniya.csv`, `pribory.csv` и `sobytiya.csv`, разделитель `;` и кодировку UTF-8. ID читаются как текст, чтобы не потерять ведущие нули.

## Этапы расчёта

### 1. Получить расход за сутки

В файле показаний хранится накопительный итог. Для каждой пары соседних показаний одного прибора считается:

```text
разница = текущее показание − предыдущее показание
```

Расход за сутки записывается только если даты идут подряд. Если между чтениями несколько дней, общая разница сохраняется отдельно, но не приписывается одному дню. Пропуски не заполняются.

Показания имеют точность 0,001 м³. Разницы в пределах ±0,0005 м³ трактуются как нулевые.

### 2. Поставить флаги аномалий

| Проверка | Критерий |
|---|---|
| Отрицательная разница | Суточное изменение меньше −0,0005 м³ |
| Всплеск | Не менее 1 м³ за сутки и минимум в 5 раз выше медианы положительного физически допустимого расхода этого прибора |
| Физический предел | Выше 37,5 м³/сутки для DN15 или 62,5 м³/сутки для DN20; если модель неизвестна, используется предел DN15 |
| Кандидат на утечку | Положительный допустимый расход каждый день 30 или больше дней подряд |
| Долгое нулевое потребление | Показание не меняется 30 или больше дней подряд, но прибор передаёт хотя бы один пакет в сутки |
| Резкое изменение среднего | До и после середины периода средние отличаются минимум в 3 раза и на 0,1 м³/сутки; в обеих частях есть минимум по 30 суточных интервалов |

Порог для всплеска требует и большого абсолютного расхода, и сильного отличия от привычного уровня прибора. Это не даёт отмечать как всплеск каждое небольшое колебание.

Положительный расход 30 дней подряд — только кандидат на утечку: регулярное использование воды может выглядеть так же. Нулевое показание при пакетах может быть нормальным для пустующего помещения; этот сигнал нужен для проверки счётчика.

Для проверки резкого изменения скрипт делит реальный диапазон дат пополам. Здесь первая часть — 01.10.2025–01.04.2026, вторая — 02.04.2026–01.10.2026. Нулевые дни входят в среднее, отрицательные разницы ниже допуска и значения выше физического предела исключаются. Деление среднего отношения на величину меньше 0,02 ограничивается снизу значением 0,02, чтобы почти нулевой расход не создавал огромный коэффициент. Это предварительный сигнал: один высокий день может повлиять на среднее, поэтому флаг нужно проверять по ряду показаний.

### 3. Сопоставить с событиями

Точные повторные события удаляются по сочетанию `ID + дата + тип`. Для событий «магнит» сравниваются нулевые и отрицательные суточные разницы в тот же день, а отрицательные разницы дополнительно проверяются в пределах семи дней. Дни с событием сравниваются с обычными днями у тех же приборов. Это проверка совпадений, а не доказательство причины.

### 4. Сохранить результаты

Скрипт создаёт в выбранной папке CSV с суточными расчётами, интервалами с флагами, сводкой по приборам, категориями, связью с событиями и кратким README. Полные таблицы могут быть большими; в репозитории оставлены компактные сводки.

## Результат на исходном наборе

Период — 01.10.2025–01.10.2026; **3 000 приборов** и **693 443 показания**.

| Сигнал | Интервалы / приборы | Примеры ID |
|---|---:|---|
| Отрицательная разница | 190 / 79 | 2491162, 8908023, 2159987 |
| Всплеск | 917 / 210 | 7726046, 2030325, 1184793 |
| Выше физического предела | 305 / 55 | 2491162, 8908023, 2159987 |
| Положительный расход 30+ дней | 1 168 приборов | 1968874, 7496751, 2931056 |
| Нулевое показание при пакетах 30+ дней | 694 прибора | 9686922, 7558835, 9354769 |
| Изменение среднего | 89 приборов: 73 вверх, 16 вниз | 3761383, 2030325, 7826125 |

Категории пересекаются: один прибор может попасть сразу в несколько строк.

### Дополнительные наблюдения

- Из 690 443 пар последовательных показаний 616 414 были за соседние даты, а 74 029 имели пропуски дат.
- В таблице событий обнаружено 23 223 точных повтора из 34 009 строк.
- На 4 611 датах «магнита» удалось сопоставить событие с суточной разницей: отрицательных разниц не было, нулевых было 1 612 (35%). Общей убедительной связи «магнита» с падением показаний не видно.
- У приборов 2491162 и 8908023 были почти компенсирующие друг друга скачки на миллионы кубометров вверх и вниз. Это больше похоже на сбой показания или обработку сброса, чем на реальный расход.

Отрицательное показание не доказывает обратное движение воды: в [паспорте АКВА](https://waviot.ru/download288/) указано, что обратный поток не вычитается из накопленного объёма. Пределы для DN15 и DN20 также взяты из этого паспорта.

## Файлы

- `analyze_water_meter_data.py` — расчёт.
- `results/category_summary.csv` — пороги, количества и примеры ID.
- `results/event_linkage.csv` — сводка сравнения событий и показаний.
- `results/generated/daily_consumption.csv` — расчёты по интервалам.
- `results/generated/anomaly_intervals.csv` — интервалы с флагами.
- `results/generated/device_summary.csv` — сводка и флаги по каждому прибору.
